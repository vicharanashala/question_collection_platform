## Volunteer registration — `organizationState` now an array

The web `CompleteProfileWizard` collects `organizationState` as `string[]` (one
org can have offices in multiple Indian states). Backend `RegisterDto` was
`@IsString() @MaxLength(100)`, which rejected the array. Fixed end-to-end:

- Migration `1784402000000-ChangeOrganizationStateToArray.ts`:
  `users.organization_state` → `text[]` (wraps existing scalar as a 1-element
  array).
- `User` entity + Mongo schema: `organizationState: string[] | null`.
- `RegisterDto` / `UpdateMeDto` / `UpdateProfileDto` accept array. `RegisterDto`
  also accepts a single string (mobile backward-compat) via a `Transform`.
- `PublicUser.organizationState: string[] | null`.
- Web `types`: `User.organizationState` and `AuthUser.organizationState` →
  `string[] | null`. Profile edit dialog reads/writes comma-separated text.
  `PublicProfilePage` and `UserDetailPage` render with `.join(', ')`.

Verified:

- `npx tsc --noEmit -p tsconfig.app.json` (web) — 0 new errors
  (5 pre-existing unrelated errors remain).
- `npx jest --testPathPattern=auth.controller` — 7/7 passed.

## Wizard language — live app-wide switch

User reported that selecting a language in the Step 4 "Preferred language"
dropdown of `CompleteProfileWizard` had no visible effect — the whole app
stayed in whatever language it was already in. Root cause: the dropdown only
updated local form state, never called `setLanguage()` from `useLanguage()`.
Same dead-code pattern existed in `ProfilePage.tsx`'s `handleSaved`
(`localStorage.setItem('language', ...)` without ever calling `setLanguage`).

The i18n infrastructure was already complete (`@/i18n/index.ts` + `useLanguage`
hook with `setLanguage` → `i18n.changeLanguage` + `LanguageProvider` in
`main.tsx`). Only the wiring at the two dropdown call sites was missing.

Fix (2 files):
- `web/src/components/profile/CompleteProfileWizard.tsx` — import `useLanguage`;
  seed `INITIAL_FORM.languagePreference` from the active i18n language; add
  `setLanguage` to `WizardFormStateProps`; `Step4`'s `<Select onValueChange>`
  now calls both `setField` AND `setLanguage(v)` for live preview; thread
  `setLanguage` through `stepProps`.
- `web/src/pages/profile/ProfilePage.tsx` — import `useLanguage`; `EditProfileDialog`
  language `<select onChange>` calls `setLanguage(v)` for live preview;
  `ProfilePage.handleSaved` calls `setLanguage(updated.languagePreference)`
  instead of the dead `localStorage.setItem('language', ...)` line.

Verified:
- `npx tsc --noEmit -p tsconfig.app.json` — 0 new errors (6 pre-existing
  unrelated errors remain).
- `npx eslint <two files>` — 0 new errors.

Behavior: pick Hindi in the dropdown → entire app re-renders in Hindi
immediately (via `i18n.changeLanguage` firing the `languageChanged` event in
all `useTranslation()` consumers); `localStorage['appLanguage']` is persisted;
next page load boots in the saved language.

Out of scope (not addressed): translating the wizard's own hardcoded English
text. The wizard doesn't use `useTranslation`, so "Preferred language",
"Choose language", etc. stay in English even when the rest of the app is in
Hindi. That's a separate i18n-coverage task requiring new keys across all 22
locales.
